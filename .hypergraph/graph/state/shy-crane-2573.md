## Current

The shell is a Blender fork under `shell/` carrying the `mesh_agent` add-on. It is the application a user launches, and it ships the engine inside its own bundle, discovered through a `cadex-engine.json` manifest so a built application needs no configuration [rec: simple-hollow-8675] [rec: merry-eagle-4093].

- It is a **protocol client and nothing else**. It may not import anything from `src/`; `cadexd_client.py` is deliberately a plain GPL NDJSON client with no cadex imports. Being in one repository does not relax this [rec: simple-hollow-8675] [rec: merry-eagle-4093].
- Product surface: viewport, chat, parameter sliders, model tree and script view; **native macOS File and Edit menus** since ADR-166 (in-window until then) [rec: open-dew-7293] [rec: curious-cloud-7186]; a saved-layout startup file rather than a Python template [rec: open-dew-7293]. Plus the Wiring editor [rec: crisp-glacier-6395], the Environment/Policy/Training/Live editors and the force-arrow overlay [rec: mellow-hawk-8610], `render_views` and the section-cage overlay [rec: solemn-chart-6274], **File > Link Part... / File > Refresh Linked Parts** with the `link_part` backend trio behind them [rec: ancient-current-9419], the Dimensions overlay with its Measure button [rec: forest-wind-3489], **File > Export Printable Parts...** with a printable checkbox per accepted output in the Parameters editor [rec: still-wave-6655], and the view toggles — collision, dimensions, section cage, section, exploded, blueprint — since ADR-165 packed as one two-per-row **Interface grid** in the Parameters panel, each with its settings box below when on [rec: grand-peak-3688] [rec: zesty-cove-4881] [rec: windy-wolf-5012] [rec: civic-glade-9153].
- **The presentation views are registry-wired** (ADR-150): `cadex_views.py` holds one record per view — collision 20, section 30, explode 40, dimensions 50, blueprint 60 — with optional `on_hydrate`/`on_preview`/`suspend` hooks, and `cadex_backend.hydrate`, `_finish_preview` and `capture.render_views` walk the registry instead of carrying five copies of the same hand wiring. Per-record try/except preserves each view's stated failure terms (a malformed record costs its view, never the geometry), `suspend_for_render()` returns one undo unwinding in reverse order, and the accepted `{display, revision}` write is hoisted outside every view's failure domain. Proven no-behavior-change by the untouched gate before any new view landed [rec: windy-wolf-5012].
- The model reaches the shell through **21 MCP tools** in `tools.py` [rec: ancient-current-9419] [rec: grand-peak-3688] [rec: zesty-cove-4881] [rec: windy-wolf-5012] — the newest are `blueprint_view` (in neither `MUTATING_TOOLS` nor `_ENGINE_TOOLS`, the `section_view` classification) and `make_blueprint` (in `_ENGINE_TOOLS` only — it writes the store, and a store write is not a scene edit, the `import_geometry` precedent) [rec: windy-wolf-5012]. **`get_script` takes optional `offset`/`limit` line arguments** (ADR-140): no arguments serves the whole script exactly as ADR-044 requires, and either argument serves a window behind a banner carrying the range, the totals and the next offset to call. It closes a gap where the *host's* tool-result cap — not ours — had no compliant response, and an agent improvised by deleting comment blocks out of a user's script to make a **read** smaller [rec: shy-glade-0050].
- **`cadex_dimension.py` draws a declared measurement as a drawing sheet would** — extension line at each anchor, dimension line between them, the number in the middle with the line broken around it. Everything except the two anchors is computed **in screen space**: the offset direction is perpendicular *on the screen*, so it cannot go edge-on however far you orbit — by construction rather than by care — and gaps, ticks and text are pixel constants, so a 2 mm boss and a 2 m beam read identically at any zoom. Below `MINIMUM_SPAN_PX`, which is what looking straight down the measured axis gives you, it degrades to a leader still carrying the number, so the value survives every viewing angle. One `POST_PIXEL` pass where the force arrows need two, because a dimension is not a world object [rec: forest-wind-3489].
- It creates **no Blender objects**, so unlike `cadex_collision` and `cadex_cage` it needs no sibling collection and cannot be swept by the contract GC. The Measure button queues a request on the pin queue rather than writing the script, so **the script keeps exactly one author** [rec: forest-wind-3489].
- **`cadex_section.py` cuts the model open, and the cut face is filled** (ADR-148). A hidden, scaled unit-cube cutter plus a Boolean DIFFERENCE modifier on each hydrated solid, and an eight-node geometry-nodes clip on each edge wire — two mechanisms because the model is drawn as two kinds of object and a boolean has nothing to say about a mesh with no faces. Measured **6.3 ms** per offset change, against the 650 ms slider bar it shares a viewport with. It is a **view, not a feature**: nothing reaches the engine, nothing is written to the script, and the gate asserts the accepted revision is unchanged either side of switching it on. Because it is modifiers rather than an overlay it survives a rebuild for free — hydration swaps the mesh datablock and keeps the object — so `cadex_hydrate` needed no change at all. `render_views` suspends it, because a cut model is not what was built [rec: grand-peak-3688]. It changed **nothing in `modes.py`**: the Cadex system-prompt overlay is capped at 3500 characters and sits at 3447, so the workflow sentence written for it did not fit and the cap was not raised [rec: neat-tower-5715].
- **`cadex_explode.py` spreads the assembly apart, and the engine authored every number** (ADR-149). A toggle plus a factor slider 0→1 interpolating the engine's exploded-view display record: staged windows (stage *i* of *N* owns factor [i/N, (i+1)/N]), lerp positions, hemisphere-corrected slerp orientations, leader lines as one wire object in a sibling `Exploded` collection growing with each component's own staged progress. Poses ride `matrix_world` — the channel hydrate already owns — and are re-applied by the hydrate hooks, so engine poses land first and the spread lands on top, always; delta channels were rejected as a second owner for one question. It **refuses while a simulation is baked**: F-Curves and `matrix_world` writes cannot share an object honestly, so mutual exclusion rather than layering. One exploded view per model; two is refused naming both. `render_views` suspends the spread, and the gate's first exploded assertion compares the factor-0.5 viewport pose against the pure half's own prediction — the re-application risk made a test [rec: zesty-cove-4881].
- **`cadex_blueprint.py` draws the model as white outlines on a drawing-office ground** (ADR-150): blueprint-blue, cutting-mat-green or grey, with an optional 10 mm grid. Pure per-space `shading`/`overlay` state from one 31-field table (`shading_values`), the replaced look captured on the scene and restored exactly on toggle off — so it **layers over the section and the explosion by construction** (an exploded blueprint works), and it needed everything already ON in the fork: Workbench flat shading, `background_type='VIEWPORT'`, `show_object_outline`, and the true-BREP `… Edges` wires, which draw in the *overlay* pass — so this is the one view that turns `show_overlays` on and pins every sub-overlay explicitly. `render_views` suspends it; `render_blueprint` is the renderer that wants it — the four fitted cameras in blueprint style, deliberately **keeping** the section cut and the exploded spread in shot (it draws the current presentation, the stated contrast with `render_views`), whose PNG `make_blueprint` stores through the engine's `put_blueprint` op, attached to the accepted revision. Verified end-to-end in the launched bundle: sheet rendered, stored, entry attached to the accepted revision, viewport restored exactly, accepted revision unchanged [rec: windy-wolf-5012].
- **`cadex_sheet.py` makes that sheet agent-composed and dressed like a drawing** (ADR-151): up to 6 views — the six named orthos, the three-quarter, or a custom azimuth/elevation — each cell with its own hidden outputs (`hide_set`, never hydrate's `hide_viewport` channel), exploded factor and section override; five layout templates tiled by shared integer boundary arrays (no-gap/no-overlap by construction), **hero-right** the default so the perspective is finally big; the stored PNG dressed with a zone-marked page grid (1, 2, 3 along the top, A, B, C down the left), the project name, and `CADEX <version> · rev · date · theme` read off the engine manifest through the new `cadexd_client.engine_version()`. Per-cell state is one flat snapshot → apply-per-cell → restore in the renderer's finally — never per-view undo stacks — with `quiet()` on section/explode exposing the settle guard their own `toggle()` used inline; spec validation runs BEFORE the background refusal, so refusals are gate-testable headless. Theme grounds darkened ~20–25%. ## Negative knowledge

- [scope: shell/ edits outside mesh_agent | confidence: high | evidence: open-key-6334] Every line added to the inherited Blender tree is a future merge conflict. Adding one is a decision to bring back, not a fix to slip in — the empty-diff rule was retired but the boundary it stood proxy for was not, and BLENDER-TREE.md section 2a must stay eight files.
- [scope: gate coverage | confidence: high | evidence: solemn-chart-6274, grand-peak-3688] The gate runs blender --background, so anything needing a real VIEW_3D is not covered by it. Verify those by driving the built application and say so, rather than implying coverage the gate does not have. Read forward as well as backward: where two mechanisms would both do the job, the one the gate can *see* is worth real cost. The section view is a boolean partly because `rv3d.clip_planes` needs a `RegionView3D`, which `--background` does not have at all, and would also have been absent from every offscreen render the agent takes.
- [scope: reading the gate's result | confidence: high | evidence: forest-wind-3489] **`pixi run gate` exits 0 when a test raises mid-run.** An `AttributeError` in one test ended the suite after 355 checks with no `CADEX-BLENDER-GATE` line at all, and the exit code was still 0. Checking the exit code is not enough — the `"ok": true` line has to be read. Pre-existing and not fixed.
- [scope: any new asset suffix | confidence: high | evidence: ancient-current-9419] Widening the engine's `_STORED_ASSET_SUFFIXES` is free, but the shell carries its **own** suffix list for Save-As and it does not follow. A new asset type that is not added there is silently dropped by Save-As, and the failure surfaces later as a script that cannot run in the copy.
- [scope: asserting anything about an output from the viewport | confidence: high | evidence: ancient-current-9419, forest-wind-3489] The viewport polygon count tells you nothing about what an output *is* — the mesh in the viewport is a tessellation whatever it came from, so a 40-face linked BREP solid shows 520 polygons and a measurement shows whatever its subject shows. A gate assertion on `obj.data.polygons` looks like it proves this and does not; **this assertion has now been written and thrown away twice in this tree.** For a drawn overlay the check that works is calling the drawing function with a made-up region and view matrix — which is why `drawing_for` is a function rather than something living inside a draw handler.
- [scope: an overlay that must read from any angle | confidence: high | evidence: forest-wind-3489] A plane fixed in the model is the wrong home for a dimension: any such plane goes edge-on if you orbit far enough. Compute in screen space instead, and the failure mode is removed by construction rather than defended against. Likewise a circle's in-plane basis must not come off a fixed reference axis — a bore drilled down Z is the single most common thing anyone measures, so the naive choice fails on the first real model rather than an exotic one; take the basis off the world axis least parallel to the circle's own.
- [scope: any per-tool exemption from a result cap | confidence: high | evidence: shy-glade-0050] `MAX_RESULT_CHARS = 4096` governs every mesh tool **except** `get_script`, and that unannounced exemption is what an agent got wrong — it concluded "the engine only shows me a 4 KB window", which was false, and never checked. The general lesson is worse than the specific one: **a tool that cannot serve part of a thing invites the model to make the thing smaller**, and the model has write access. 122 lines and 4.8 KB of a user's design rationale were deleted to advance a read.
- [scope: adding a table to docs/INTEGRATION.md | confidence: high | evidence: forest-wind-3489] Its two contract tables are scraped by regex on any line starting with `` | ` `` — across the whole document for ops, and within the response section for keys. A new markdown table anywhere in the file is read as protocol rows. Document nested records as a bullet list.
- [scope: adding a line to the Cadex system-prompt overlay | confidence: high | evidence: neat-tower-5715] `modes.CADEX_OVERLAY` is capped at **3500 characters** by `bl_mesh_agent.py` and sits at **3447**. The next workflow sentence is not a sentence, it is a decision about which existing one to remove — and the bar that text is held to is the collision line's: it earned its place with two shipped bugs. Note also that this guard lives in `bl_mesh_agent.py`, which `pixi run gate` does **not** run — `pixi run gate` was green with the over-budget overlay in place.
- [scope: measuring the model from the shell | confidence: high | evidence: grand-peak-3688] **`obj.bound_box` reflects EVALUATED geometry, not the object's data.** A 20 mm cube with a boolean that cuts it at z = 5 reports a top of 5 — measured, not assumed. Anything that both modifies the display objects and derives numbers from their extent feeds back on itself: the centre of an axis drifts into the surviving half, and a range a person is dragging against moves as they drag. Read the mesh datablocks (numpy `foreach_get`) when the number must mean *the model as built*, and suspend any such modifier before measuring for a camera fit.
- [scope: where model state may live | confidence: high | evidence: forest-wind-3489] Scene data in the `.blend` is much cheaper than a script declaration and is the wrong answer for anything that is part of the model: it would be the only model state not in the script — lost by a Save-As, unauthorable by the agent, and unable to travel in a `.cxpart`. In the script it is anchored by selector and recomputed, which is what makes it follow a parameter.
- [scope: a view module's clear() when the view was never applied | confidence: high | evidence: windy-wolf-5012] A restore path with a fallback must be gated on "was anything ever applied", not run unconditionally: blueprint's first `clear()` applied the fallback product look on a settings write with the view off, stomping the user's viewport — which the subsequent toggle-on then captured as "the look to restore". A property update callback fires on any assignment, including one made while switching the view ON, so the off-path runs at surprising times. The gate's exact-restore assertion is what caught it.
- [scope: the Edges wires and viewport overlays | confidence: high | evidence: windy-wolf-5012] The true-BREP `… Edges` wire objects draw in the **overlay** wireframe pass (`overlay_wireframe.hh` skips wire objects when overlays are off). Any styling that needs them visible must turn `show_overlays` ON — and must then hold every sub-overlay explicitly, because whatever is not pinned draws whatever the user last had there.
- [scope: a per-cell shape ask on a composed sheet | confidence: high | evidence: green-tree-7595] The cells of a sheet compete for **one fixed field**, so a per-cell aspect cannot be solved, only approached: place, measure what each cell came out at, scale its track, place again. A cell that owns a whole track gets what it asks (a triptych column asked 1:3 and was drawn 1:2.97); a cell **sharing** a track cannot (the same ask in a three-cell column reached 1.31:1, because the width is not that cell's to spend). Spending the full ask on the stacked cell's own axis was measured — it reached 0.98 and squashed two innocent siblings to 96 px strips — and rejected. Report the shape drawn, in the text the agent reads back, rather than implying the ask was met.
- [scope: a tile drawn under a label the sheet dressing draws | confidence: high | evidence: green-tree-7595] A cell's own label is drawn **over** its tile by `_dress_sheet`, so any tile that starts its content at the top edge collides with it. The parameters panel had done exactly that since ADR-153 and no test could see it: in a short cell the first slider row was drawn through the word "parameters". A windowed probe of the built bundle is what found it, and `top_pad` — the parameter the text panel needed anyway — is what fixes it.
- [scope: text drawn into a rendered cell | confidence: high | evidence: humble-peak-6095] Dressing that needs room beside the model has a size below which it is worse than nothing. Part-name callouts read well in a 341 px column and landed **on** the part in the 85 px columns of a 256 px sheet — the same code, the same arithmetic, a cell that simply has no label band. Measure it on the rendered sheet and give the feature a floor that drops it honestly (counted, and said in the tool's reply), rather than trusting text to shrink with its cell.
- [scope: a panel row added to CADEX_PARAMS_PT_parameters | confidence: high | evidence: still-wave-6655] **No suite in this repo draws a panel**, so a draw bug is invisible to `pixi run gate` and to `bl_mesh_agent.py` alike — both can prove the operator registers and the backend works while the row appears nowhere. Two such bugs shipped into a windowed probe of the built bundle and neither was catchable otherwise: `CADEX_PARAMS_PT_parameters.draw` **returns early** when a model declares no parameters, so anything added below that branch is absent from exactly the simplest model (`result = {"bracket": part.box(...)}` — which is the model somebody wants to print); and a full-width `emboss=False` operator centres its label, putting the text at the far side of the panel from its own icon and reading as two unrelated widgets (`row.alignment = 'LEFT'`). Probe the bundle and look at it.

- [scope: reading a latency bar off a loaded machine | confidence: high | evidence: gilded-wind-5121] The gate's `slider_latency` check is the one number in `CADEX-BLENDER-GATE` that a busy machine can fail on its own. A run at load average 13.7 measured 1.124 s against the 0.65 s bar — and **every** other number in that same run was 2–3× its usual value (open 3.0 s vs 2.0 s, refine 3.1 s vs 1.4 s). The re-run on a quiet machine came back at 0.538 s. Read the whole line before believing a latency failure, and re-measure rather than chasing a regression that is not there.

- [scope: bit-equal restore assertions over the viewport | confidence: high | evidence: morning-walrus-8074] Two kinds of viewport state cannot be asserted bit-equal naively. A parented wire child's `matrix_world` is an EVALUATED value — a snapshot taken between a matrix write and the next depsgraph pass captures the stale pose and blames the restore for it; settle (`view_layer.update()` + `evaluated_depsgraph_get()`) before capturing. And a **derived artifact** like the section cutter's matrix is computed from model bounds at refresh time, so live state can legitimately hold a stale value no restore reproduces — a restore that recomputes is more correct than the staleness, and the fixture must make the live value reproducible rather than the restore matching it.
- [scope: an agent that cannot reach its tools | confidence: high | evidence: weathered-sand-9705] **It does not say so.** It writes the call out as prose — `<invoke name="mcp__mesh__get_script">` — invents a plausible result, and answers as though the work happened. There is no error, no non-zero exit and no empty reply, so the turn reads *better* than a real one. Caught only from a user transcript in which the model quoted back a complete "current script" that did not exist, in an API this product does not have, on 1670 tokens of context. `agent.py` now watches the streamed text for `<invoke name=` — which a real call can never produce, since it arrives as a `tool_use` block — and says so once per turn.
- [scope: two safety settings that each look right | confidence: high | evidence: weathered-sand-9705] `--tools ""` is correct and MCP schema deferral is a reasonable default; **together** they disable the only key to the tools the product depends on. Neither is wrong alone, so no review of either would have caught it. `test_the_mesh_tools_are_not_deferred_behind_a_disabled_tool` pins the *join*, not the halves.
- [scope: the agent test suite | confidence: high | evidence: weathered-sand-9705] The only test that would have caught this is the one that never runs: `MESH_AGENT_LIVE=1`. Every other agent test drives the mock backend, which by construction cannot reproduce a CLI flag interaction. An opt-in live test is a test you do not have.
- [scope: proving an add-on fix reaches the user | confidence: high | evidence: weathered-sand-9705] `pixi run gate` loads the add-on **from the source tree** and only the engine from the bundle, so a green gate says nothing about the installed application. `pixi run install-app`, then read the fix out of `/Applications/Cadex.app` — better, import the module inside the bundle and print what it resolves.
- [scope: code that runs during add-on register() | confidence: high | evidence: lucid-otter-3511] `bpy.data` is `_RestrictData` while an add-on registers — reading `filepath` raises, and an exception there aborts the REST of `mesh_agent.register()`, silently costing the session its save/load handlers while everything registered earlier keeps working. Defer the decision through `bpy.app.timers` (the template's own idiom), which also never fires under `--background`.
- [scope: screen-layout ops driven from a script | confidence: high | evidence: hollow-spring-0679] `SCREEN_OT_area_move`/`area_split` poll on `screen->active_region == NULL` — the mouse must sit on an area EDGE, and no context override can fake that. `window.cursor_warp()` onto the edge being moved, one event-loop beat, then the ops run under a plain window+screen override. The poll error is context-opaque; the fix is the mouse position.
- [scope: rasterizing an SVG on a stock Mac | confidence: high | evidence: wandering-mist-0460] `qlmanage` renders SVGs but bakes an opaque white page behind the art — the PNG reports hasAlpha while every pixel is alpha=255, and the defect only shows when drawn over a dark ground. A border-connected flood key recovers it; better, take the art out of an existing `.icns` with `iconutil`, which keeps true alpha.
