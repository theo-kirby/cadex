## Negative knowledge

- [scope: the eight-candidate cap on `offset_candidates` | confidence: high | evidence: copper-canyon-0231, dry-rain-0489, rising-rain-0117] **Resolved, and truncation was the cause.** The cap was set before quarter-span siblings tripled the generated set and was not revisited. On the two-object `ot4-quill` the ranked list came back six long, so it did not bind; on the ten-object `ot4-swing2` rig it came back at exactly 8, and the previous entry left truncation and the coverage ordering unseparated. A probe that cut *every* candidate separated them: the base plate and mount cluster filled all eight places, and 12.75 / 13.4 / 14.525 / 18.4 mm — the four planes that cut `cmp_swing_arm` — were never evaluated, so **ranking alone could not have reached the arm**. ADR-273 keeps every object's own centre unconditionally and applies the bound (now 48) to siblings only. The general lesson outlives this cap: a work bound applied to a candidate list ranked by a proxy can silently delete the answer, so bound the *derived* members and never the ones an object contributed itself.

- [scope: a stale lock file left behind by a killed CLI run | confidence: high | evidence: humble-star-3313] It is inert and needs no cleanup command. `session.py`'s project lock is an advisory `flock`, released by the kernel when the holder dies, so the leftover pid file after a killed walk names a dead process and nothing else — confirmed by holder pid 2021869 being dead while the project reopened normally.

- [scope: cli/ on macOS | confidence: medium | evidence: jolly-walrus-3692] Nothing in the CLI is macOS-hostile, but it has never been run there by hand and 'should work' is not evidence. Expect the macOS CI job to be the thing that finds anything.
- [scope: copying code into cli/ | confidence: high | evidence: jolly-walrus-3692] Copying a line from the GPL shell's client into LGPL cli/ relicenses the engine side. It is not a judgement call — derive from the engine-side precedents instead.
- [scope: giving the CLI agent a tool that spawns the trainer | confidence: high | evidence: amber-moon-0981] Not taken by decision: the agent has no shell, and a fifteen-minute subprocess inside a model turn is the wrong shape. The leg is the caller's or a pipeline's, one command, and the overlay says so.
- [scope: a warm start on the remote train leg | confidence: high | evidence: green-delta-7130, candid-otter-2615] Refused as a usage error before any leg: `remote_train.sh` copies the bundle and the model out, not the `--init-from` policy, so `--remote` trains cold until the dispatcher carries the pair. `--detach` is not passed through either; a walk waits for its leg. `--dry-run` does not bypass the check — the usage error fires before the plan is built.
- [scope: certifying a payload's coherence at CLI resolution | confidence: high | evidence: tiny-haven-0347, keen-pebble-3574] Equal manifest and module schema strings do not establish identical code or complete worker imports. Not taken: version fingerprints or a new validation policy; the false guarantee was removed from the guidance instead, and the packaged lifecycle gate remains the check that proves a payload.
- [scope: a `params --drop-policy` flag or an engine op for iterate | confidence: high | evidence: keen-sail-4481] Not taken: `set_params` already accepts a dropped output, so a script convention (`policy_on`) does the job with no CLI flag and no engine change; adding a `flag(...)` parameter type was also declined because parameters are numeric only and the convention does not need one.
