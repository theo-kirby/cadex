**The currency audit, and the one thing it caught.** ADR-201's bullet called `cadex -p` "the one leg that can be done in either window" and said nothing about which model each window spends — and the two windows resolve the turn model *separately*. The CLI resolves `--model`, then `$CADEX_MODEL`, then `claude-fable-5`; the shell resolves a Blender preference whose default is `DEFAULT_MODEL = ""` — whichever model the agent CLI itself defaults to — and **nothing under `shell/` names `CADEX_MODEL`**. So a box that names its model once names it for the terminal legs only, and the credit refusal that motivated ADR-249 still refuses the in-app turn while the walk beside it runs. The claim was already false before ADR-249 (the shell's default became `""` in `c99e6e60`); ADR-249 repeated it, and so did the source comment it was written from. Fixed as documentation, not behaviour — `docs/CLI.md` §2 gains a bullet, the `DEFAULT_MODEL` comment in `cli/cadex_cli/agent.py` stops claiming one answer for both front ends, ADR-249 and ADR-201 each carry a dated correction, the ROADMAP bullet says what was wrong, and two pins in `cli/tests/test_project_docs.py` hold the doc sentence *and* the underlying `mesh_agent` facts, so a shell that later learns `$CADEX_MODEL` fails the doc rather than quietly outdating it. `cli/tests` 218 passed, 0 skipped; LGPL CLI zone and docs only, no engine, protocol, payload or `shell/` diff [rec: early-quill-3654].

## Negative knowledge

- [scope: `$CADEX_MODEL` across the three modes | confidence: high | evidence: early-quill-3654] The modes are one shape in artifacts and paths but **not** in model resolution: `$CADEX_MODEL` reaches the terminal's `cadex -p` and not the in-app agent, whose `DEFAULT_MODEL` is `""` and which names no environment variable. Naming a model once on a box does not cover the GUI window. Documented rather than fixed, deliberately — teaching `shell/` a new environment variable is a `shell/` behaviour change with its own gate and its own unit, and the Blender preference already exists for a person who wants the two to match.
- [scope: stale shell mutations and concurrent project writes | confidence: high | evidence: still-badger-2386] Real-engine overwrite was not reproduced. Dormant replay is removed and stale guards retained; Rebuild Model or reopen is required before GUI edits resume. Simultaneous acceptance/rebuilds remain un-serialized and require sequential use.
- [scope: a warm start with `--remote` | confidence: high | evidence: green-delta-7130] Refused before any leg: `remote_train.sh` copies two files out and the `--init-from` policy is not one of them, so the remote leg trains cold. Carrying the pair is a change to the dispatcher and its own unit.
- [scope: `--detach` through the walk | confidence: medium | evidence: green-delta-7130] Not passed through: a walk waits for its leg; a long run is dispatched by hand and continued from `cadex asset --put`. `--timeout` ends the local ssh, not the run. The CLI reads none of `.remote.env`, keeping ADR-089's fail-loud shape.
- [scope: the scaffold writing the training mode as a value | confidence: medium | evidence: wild-marsh-9611] Not done: the scaffold is written once on first visit and never overwritten, and a project can be trained both ways over its life, so the section is a template the agent fills in and the per-row `(remote)` marker records which mode a number came from.
