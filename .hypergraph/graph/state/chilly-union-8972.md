## Negative knowledge

- [scope: `run.py`'s closing smoke on an invocation that exhausts a design | confidence: high | evidence: weathered-fountain-7838] It is not re-runnable on a project that has already smoked. The block opens with `smoke.mkdir()` and no `exist_ok`, and `attempt.json` is written after it, so a second exhausting invocation on a project carrying `evidence/smoke` raises `FileExistsError` **after** the model turn has been spent and measured and **before** any of it is persisted — the slot is gone and the receipt still says `running`. Reason about the exhausting path specifically: it is the only path that both runs the smoke and writes the receipt last, so the ordinary paused invocations that ran fine prove nothing about it.

- [scope: a source-output name absent from `derived_catalog_sources` | confidence: high | evidence: still-rock-6891, restless-slope-6471] Absence is **not** evidence that the output is a printed part. The producer follows a definition's base-operand spine only, so a catalog body fused into a printed solid as a *second* operand — or modified some other way — is a purchase it cannot name, and silence there is not proof of catalog identity. The one absence that *is* conclusive is a catalog body reachable only as a cutter: that is a clearance tool and implies no purchase. ADR-381's clause 3 read absence as "an ordinary printed part" and was withdrawn by ADR-382 for exactly this.

- [scope: the swept fit verdict on a receipt written before ADR-378 | confidence: high | evidence: vast-water-9886] `sweep pass` meant "no pair overlapped anywhere in a range" and nothing more. A motion that closes a declared clearance, or takes an undeclared pair under the 0.1 mm default without ever touching, read as a pass with the minimum distance printed beside it — reproduced at 0.04 mm on real OCCT solids. A pre-ADR-378 swept receipt carries the number but not the judgement.

- [scope: a `cadex smoke` `support: pass` on a receipt written before ADR-377 | confidence: high | evidence: humble-harvest-9420] It means a base geom was touching the floor and had stopped moving, which a design that fell over satisfies as soon as it lands: the retained ot6 balancer rested 101.3 degrees over with its chassis on the floor and passed. Such a receipt says nothing about whether the design held the pose it was accepted in.

- [scope: deriving unswept coverage from a sweep summary as `joints_checked - joints_complete` | confidence: high | evidence: golden-lodge-6986] Since ADR-371 that over-counts by the number of suppressed joints: `joints_checked` counts every row and a suppressed joint's row is `skipped`, neither complete nor missing. Read `joints_skipped` and subtract it, as both readers in this tree and `docs/CLI.md` now do. Since ADR-375 the opposite error is also available: an unbounded movable joint's `incomplete` row *is* missing coverage and must be counted, so only `skipped` comes out of the arithmetic [rec: solar-arrow-5671].

- [scope: the product-agent session's `describe_api` tool result under the harness's tool-result cap | confidence: high | evidence: mellow-summit-9733, crimson-wind-8698, flat-cove-2253] A character budget derived from the documented 25,000-token cap at four characters a token does not predict the refusal: 82,523 characters was refused and 20,717 accepted in one turn. The agent cannot read the overflow file (Grep, Read, Bash and Agent are disabled in that session), so an oversized reply costs the `inspect scope=api` paging the note names, about three minutes, and the cut below the cap had to be of a different kind than a trim: ADR-360's pages are sized under the largest result the harness accepted (21,742 characters), not under the documented cap [rec: slender-union-6486].

- [scope: the 494 passed / 15 skipped CLI count at `ad4e08e1` | confidence: medium | evidence: plain-arrow-4971] That run drove a detached worktree with the pixi environment's interpreter directly rather than `pixi run`, with `-q` and no `-rs`, so the skip reasons were not captured; 14 of the 15 are probably environment-gated tests `pixi run` satisfies, since the same suite under `pixi run` on the following tree gives 521 passed / 1 skipped. - [scope: the eight-candidate cap on `offset_candidates` | confidence: high | evidence: copper-canyon-0231, dry-rain-0489, rising-rain-0117] **Resolved, and truncation was the cause.** The cap was set before quarter-span siblings tripled the generated set and was not revisited. - [scope: ADR-322's original per-directory entry cap as evidence of bounded disk accounting | confidence: high | evidence: red-shade-9740, fierce-bloom-1023] Iteration 100's `civic-nest-8285` alone is not evidence that the reader's work is bounded: its independent capped walks sorted whole directories before capping, and a truncated reference count was shown as a complete total. - [scope: a stale lock file left behind by a killed CLI run | confidence: high | evidence: humble-star-3313] It is inert and needs no cleanup command. `session.py`'s project lock is an advisory `flock`, released by the kernel when the holder dies, so the leftover pid file after a killed walk names a dead process and nothing else — confirmed by holder pid 2021869 being dead while the project reopened normally.

- [scope: cli/ on macOS | confidence: medium | evidence: jolly-walrus-3692] Nothing in the CLI is macOS-hostile, but it has never been run there by hand and 'should work' is not evidence. Expect the macOS CI job to be the thing that finds anything.
