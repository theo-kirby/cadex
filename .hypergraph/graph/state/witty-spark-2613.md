## Negative knowledge

- [scope: `$CADEX_MODEL` across the three modes | confidence: high | evidence: early-quill-3654] The modes are one shape in artifacts and paths but **not** in model resolution: `$CADEX_MODEL` reaches the terminal's `cadex -p` and not the in-app agent, whose `DEFAULT_MODEL` is `""` and which names no environment variable. Naming a model once on a box does not cover the GUI window. Documented rather than fixed, deliberately — teaching `shell/` a new environment variable is a `shell/` behaviour change with its own gate and its own unit, and the Blender preference already exists for a person who wants the two to match.
- [scope: what the leg-by-leg GUI table proves | confidence: high | evidence: cool-eagle-6400] It is derived from the code on both sides and pinned to it, so a seventh `run_leg` leg fails the doc rather than quietly outdating it — but it remains a **reading**, not an execution. No GUI-attached walk has been run, here or anywhere; the table says what the code would do with a window open, and the two differences it names (the ADR-204 stale-revision refusal after `declare`, and separate turn-model resolution) are the only ones the sources support. A fifth shell application handler must be read against the four-handler claim before that line is widened.

- [scope: stale shell mutations and concurrent project writes | confidence: high | evidence: still-badger-2386] Real-engine overwrite was not reproduced. Dormant replay is removed and stale guards retained; Rebuild Model or reopen is required before GUI edits resume. Simultaneous acceptance/rebuilds remain un-serialized and require sequential use.
- [scope: `--detach` through the walk | confidence: high | evidence: brisk-eagle-8550] **Resolved by ADR-282**, and the shape it resolved into is the knowledge worth keeping: a walk cannot both detach and finish, so it splits into a launch that stops at a marker and a `--complete` that resumes from it, and the four digest/state checks between them exist because the alternative is declaring a policy that is not the walk's own. What was true before, and is superseded: a walk waited for its leg and a long run was dispatched by hand and continued from `cadex asset --put` [rec: green-delta-7130] [rec: idle-falcon-3004]. Unchanged: `--timeout` ends the local ssh and not the run, and the CLI reads none of `.remote.env`, keeping ADR-089's fail-loud shape. No polling and no scheduler was built, by decision.
- [scope: the scaffold writing the training mode as a value | confidence: medium | evidence: wild-marsh-9611] Not done: the scaffold is written once on first visit and never overwritten, and a project can be trained both ways over its life, so the section is a template the agent fills in and the per-row `(remote)` marker records which mode a number came from.

- [scope: what `cadex train --dry-run` proves about a remote box | confidence: high | evidence: candid-otter-2615] The shape of the leg only — which files, in which order, with which flags. It does no ssh and reads no `.remote.env` by decision, so it is not a substitute for `remote_train.sh check` and establishes nothing about reachability, the box's venv or its trainer version; both docs say so in as many words. `walk` deliberately gained no `--dry-run`: a half-run walk is not a preflight and would leave a project half-written. A warm start with `--remote` is no longer refused here — since ADR-268 the dispatcher carries it and `--dry-run` plans it in both modes [rec: idle-falcon-3004].
