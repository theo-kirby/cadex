## Negative knowledge

- [scope: what the walk commits from a training leg | confidence: medium | evidence: shy-cabin-0798] Before ADR-199 the `train` leg's commit carried `job.cxpolicy`, `job.best.cxpolicy` and the store copy — three copies of one policy. The store's asset is the project (ADR-194); checkpoints and traces are not, and the `.gitignore` says so. Reversible per project, because the file is editable.
- [scope: `declare_policy` in `cli/cadex_cli/walk.py` against agent-authored scripts | confidence: high | evidence: misty-rain-9048, cool-fountain-2483] The rewrite handles inline `weights="…"` / `sha256="…"` literals only; a script that names them through module constants is refused at exit 3. The fix went into the authoring contract, not the rewrite: resolving constants would make the walk guess at a script it did not write. A test pins the refusal as intended behaviour.
- [scope: the first design-leg failure inside `cadex walk --prompt` on 2026-09-07 | confidence: medium | evidence: misty-rain-9048, ancient-wind-0117] One observed fast failure (3.76 s, after one `describe_api` call) with the child's reason discarded, and one identical retry that succeeded in 214 s. Its cause is unrecoverable: the envelope that would have named it landed afterwards. Not reproduced on purpose; the clean runs since [rec: placid-sky-7374] make it the outlier, not the pattern.
- [scope: what one prompt walk proves about a review surface | confidence: high | evidence: morning-summit-7848] The design turn is nondeterministic across runs of the same prompt: the pan-tilt prompt placed two catalog servos once and fused them into hand-authored solids the next time. A walk selected to exercise a catalog-part code path may not exercise it at all; check the inventory's catalogued count before reading its review numbers as evidence for anything catalog-shaped.
- [scope: comparing `total_reward` across prompt-walk projects | confidence: high | evidence: placid-sky-7374, empty-banner-7438, fond-star-1809] The reward expressions are different objectives in different units, so 425.997, 0.0035556 and -2380.357 compare runs of one project only, never designs against each other — the same caveat `examples/lifecycle/README.md` records for the two example mechanisms. The two leg walks make the same point on one mechanism: −5144.79 and 0.853 are the same leg under a negatively and a positively shaped objective.
- [scope: a walk project under the system temporary directory | confidence: high | evidence: lucid-pebble-4000, fond-star-1809] It is reaped between iterations, so its review findings cannot be written back into its own `DECISIONS.md`, and there is no conversation left to `--resume`. The findings survived only in this graph. An iterate unit must walk a durable project outside the checkout and outside `~/arch`.
- [scope: a design turn's own account of why an engine op refused | confidence: high | evidence: open-hollow-2140] Do not take it as a measurement. The ot4 rig's `docs/rejected.md` asserts that a single grounded box with one box collision exhausts the worker cap; a control in a fresh project builds that model in under a second. The turn writes what it inferred from the failure it saw, not what it isolated.
- [scope: walk evidence and the machine it ran on | confidence: high | evidence: open-hollow-2140, humble-forest-6896, lawful-wolf-9205] Six clean walks on one machine did not carry to the next one, and neither cause was in the walk. The design leg's model default was machine-specific (credit on one login, not another), and the dynamics stall was a native library sizing its allocations from the host's core count — so it needed a 32-core box to appear at all. "Tested headlessly" is a per-machine claim as long as the criterion words it that way, and the two machine-portability faults it caught were both worth catching.
- [scope: running the walk after a Python-only engine change | confidence: high | evidence: narrow-wing-0418] The installed runtime remains a separate copy requiring rebuild/install after source edits. ADR-251 now reports top-level Python differences or unavailable evidence before the walk, superseding the missing-comparison warning. A match proves neither binary currency nor loaded-module provenance; reporting never rebuilds or refuses [rec: narrow-wing-0418].
