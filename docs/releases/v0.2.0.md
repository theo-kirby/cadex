# Cadex v0.2.0

The release where Cadex stops being an application and becomes **three
things** (ADR-500):
- a headless **engine** on a FreeCAD/OCCT fork;
- a read-only **dashboard** to watch a design in;
- **agent bindings**, so the agent you already use (Claude Code, Codex, Pi,
  any MCP client) drives the engine.

Cadex has no agent of its own (ADR-538). The Blender shell is deleted, and
with it every line of GPL code (ADR-498). Tag `v1-blender-shell` is the last
tree that builds it.

About 2,180 commits and ADR-174…729 since v0.1.0. Run from source:

```bash
pixi run setup-engine && pixi run build-engine
pixi run app                                    # the dashboard, http://127.0.0.1:8765/
claude mcp add cadex -- "$PWD/cadex" mcp --project ~/cadex-projects/bracket
```

## The product is three things (ADR-500)

- **The shell is deleted.** It was disabled (ADR-495), then deleted:
  the shell's tree (19,446 tracked files and about 9.3 M lines), Blender's `extern/`,
  the LFS pointers and four platform library submodules (ADR-498).
  `mesh.blender` went with it (ADR-496). No live doc names the shell, and a
  test holds that (ADR-499). `docs/SHELL-PARITY.md` records where each shell
  feature went: ported, covered or dropped.
- **No GPL code.** The repository is LGPL-2.1-or-later end to end, and
  `test_licensing_compliance.py` fails if a GPL-declared file returns
  (ADR-498, `docs/PROVENANCE.md` §7).
- **The inherited tree is cut further.**
  - Deleted: `src/Gui` (ADR-213, ADR-214); Help, Start and the Microsoft GSL
    checkout (ADR-216…222); Show, XDGData, MacAppBundle, the 3rdParty GUI
    residue, VR and the designer plugin (ADR-632).
  - The staged payload no longer carries LLVM and clang (ADR-531), or
    OpenCV, PCL, Node and Perl (ADR-532).

## Agent bindings (ADR-538)

- **`cadex mcp --project DIR`** is an MCP stdio server with one tool
  surface (`cli/cadex_cli/tools.py`):
  - `describe_api`, `write_script`, `edit_script`, `set_params`, `rebuild`,
    `inspect`, `link_part` and `put_asset`;
  - `look` and `draw_blueprint`;
  - `train_start`, `train_status`, `train_stop` and `evaluate` (ADR-406,
    ADR-464, ADR-516).
- **The server is robust.** It negotiates the MCP protocol version, and it
  answers malformed input rather than dropping it or dying (ADR-673).
- **`cadex guidance`** prints all of what the agent is told. The guidance is
  engine data (ADR-446): a short, domain-neutral base (ADR-560, ADR-650,
  ADR-651) plus optional named styles a project chooses with `cadex style`.
  - The styles: `printed-legged-robot`, `creature`, `gantry-machine`,
    `vehicle` and `product` (ADR-560, ADR-625, ADR-626, ADR-652, ADR-653).
  - Its rules are principles with a reason and a check, not fixed placements
    (ADR-651).
- **No model loop of its own:** no API key and no provider SDK.
  `./cadex params --set k=v` sweeps parameters without spending tokens.
  `cadex mcp` keeps a bounded activity log, one line per tool call, written
  while the call is in flight (ADR-549, ADR-553).
- **The project is a codebase**, with scaffolded documents and a git
  repository the project owns (ADR-193, ADR-194).

## The dashboard (ADR-500, ADR-537)

- **What it is.** `cadex app` (or `pixi run app`) serves every project in a
  directory (ADR-502). It is a standard-library server with vanilla JS and
  vendored three.js: no npm, no bundler. **It is read-only** (ADR-537). The
  design spec is `docs/DASHBOARD.md` (ADR-501).
- **The interface.**
  - Blender-style areas with one-click layout presets (ADR-534, ADR-573).
  - A 3D viewport with pan, physical materials and wireframe, on a
    metre-grid dark floor (ADR-561, ADR-600…604). Four lighting setups and
    two matcaps (Aluminium, Clay), ambient occlusion, soft shadows and
    surface detail such as printed layer lines (ADR-676).
  - An Outliner listing every part, to show, hide, isolate, select and frame
    it, with the selection outlined in the viewport (ADR-676).
  - `cadex hero`, a project's presentation folder on request: stills in
    several looks, a dashboard screenshot, the concept sheet, the best
    rollout, and landscape and square hero videos with a wiped turn,
    the rollout and the training curves (ADR-677).
  - A Status editor with charts, the evaluation and the runs (ADR-572,
    ADR-606), plus a sandboxed Status panel the agent can author (ADR-607).
  - A navigation gizmo that turns with the camera and snaps to an axis
    view, even while a rollout plays (ADR-726, ADR-729).
  - An **Activations** editor: a gauge per motor, and the rollout's policy
    network run in the page on inputs rebuilt from the trace; its heat can
    paint each motor's parts in the viewport. The network has its own
    **Network** editor, and a **Settings** editor holds the colour ramps
    (ADR-727, ADR-728).
  - The bar is a status bar at the bottom, and the scrubbers sit in the 3D
    viewport's header (ADR-728). Several 3D viewports, Activations or
    Network editors can be open at once, sharing one playback (ADR-729).
  - The viewport can follow a playing design (ADR-693), and a task's gait
    reference plays as a kinematic rollout (ADR-703).
- **History and training.**
  - Live checkpoint rollouts while a run trains, with a scrubber (ADR-544,
    ADR-545).
  - The design's history on a revision timeline (ADR-546…548).
  - Evaluation films in the 2D viewport (ADR-541).
- **Portable.** Every URL is relative, so the dashboard can be mounted under
  a prefix, and the HTTP API is one documented table (ADR-551, ADR-552).
  Models are cached, tagged and compressed on the way to the page (ADR-535).

## Engine: build, verify, measure

- **Fit is measured on every build.**
  - Each build reply carries static fit, swept joint fit, coverage and
    catalog identity, bounded to fit in one tool result (ADR-346, ADR-362,
    ADR-366, ADR-435).
  - Hinge and slider sweeps are done on exact solids (ADR-349…351).
  - Fit is measured once per geometry, four sweeps at a time, with a cache
    (ADR-419, ADR-423, ADR-622).
  - Declared fit is evidence, never a gate (ADR-347).
- **Panels and housings.**
  - A panel is declared (`role=`, `covers=`), cut from an envelope in the
    worker (`part.envelope`, `part.panel`) and checked as `fit.panels`
    (ADR-633…637).
  - `closes=[...]` declares lids, doors and enclosure walls (ADR-666).
  - Moving regions are declared as `assembly.anatomy` and measured in every
    reply (ADR-613, ADR-614, ADR-655, ADR-665).
  - A panel can take a designed form (`part.envelope(form=...)`,
    `lib.form`, `part.former`), or be cut from the form itself with
    `part.skin`, which opens round what moves through it (ADR-679, ADR-684,
    ADR-687, ADR-691).
- **Large assemblies build faster.** The static fit measures panels face
  pair by face pair (ADR-678). A joint sweep measures only the samples a
  lower bound cannot settle, budgets only the pairs near each other, and
  publishes only the pairs it measured (ADR-686, ADR-690, ADR-692). A script
  that drops accepted outputs is refused before it builds (ADR-682).
- **Every build path carries a verdict brief**, so a shell build reads as
  well as an MCP `rebuild` (ADR-689).
- **Refusals are diagnoses.** A kernel or solver refusal names the failing
  call and reaches the model whole, and a refused build keeps the script's
  prints (ADR-617, ADR-618, ADR-620). The sandbox gains `math` and safe
  introspection (ADR-615, ADR-616).
- **Presentation.** `render` and `look` draw a studio hero, a concept sheet
  and a print-bed hero, all on the dark prototype floor and lettered in Noto
  Sans (ADR-412…415, ADR-430, ADR-444, ADR-568, ADR-569). Parts declare
  appearance roles and material classes (ADR-413, ADR-603).

## Parts library

- **Catalogued hardware as script vocabulary** (ADR-181): servos, a bus
  servo, Pi 5, camera, range sensor, wheel and tyre, foot pad, motor driver,
  solder-pad boards, a sourced N20 gearmotor, BLDC envelopes, involute gears
  and a rack (ADR-202, ADR-205, ADR-206, ADR-233, ADR-234, ADR-485…490).
- **Quasi-direct-drive actuators**, `lib.qdd`, in three tiers: light
  (AK45-10, AK60-6), mid (AK70-10, AK80-9) and heavy (AK10-9), with
  `.mounting()` and a continuous rating beside the peak (ADR-540, ADR-608,
  ADR-609, ADR-707, ADR-713).
- **Machine parts as data.** `CadexParts.json` plus `lib.part` covers rails,
  carriages, pulleys, belts, screws, steppers, extrusion and slot hardware,
  cylinders, spindles, casters and springs. The parts publish their mounting
  holes, and the mounting check knows their families (ADR-646, ADR-647,
  ADR-660, ADR-661).
- **Fastening.** A bolt holds only if it fits the hole, and only by its
  thread. Every build reply says what holds each purchased part (ADR-486,
  ADR-488, ADR-492, ADR-493).

## Dynamics, tasks and policies (MuJoCo 3.10.0)

- **Tasks and evaluation.**
  - A free base, with stand, reach, point-goal and `phase` tasks (ADR-335,
    ADR-462, ADR-592, ADR-598).
  - Success specs are declared in xscript. `evaluate` runs one independent
    episode per seed and films them (ADR-455…460).
  - A passed evaluation gets a hero and a shove video (ADR-570, ADR-571).
- **Onboard sensing only.** A design declares its brain, sensors and power,
  including position trackers and load sensors (ADR-407, ADR-408,
  ADR-588…591). Motion predicates cover turns, laps and distance (ADR-587).
- **Mechanisms.** All of these export to MuJoCo (ADR-473…475, ADR-593…595,
  ADR-621, ADR-640…645):
  - closed linkages, driven from the crank and checked by `cadex smoke`;
  - gears, belts, screws, rack-and-pinion and n-joint couplings, as
    equalities and tendons;
  - a `cylinder` actuator;
  - `assembly.tool`, with a `workspace` block.
- **Gaits and their evidence** (orun6).
  - `CadexGait` generates a gait reference from a gait name and the leg
    chains, within joint limits. A task carries it, tracks it on a gait
    clock and can start at a random phase of it (ADR-702, ADR-703, ADR-706,
    ADR-709).
  - A rollout trace records each drive's joint state and delivered effort
    (ADR-694). A task can observe its previous action, foot contact and joint
    acceleration, up to 128 channels (ADR-696, ADR-698, ADR-699, ADR-701).
  - A success spec can bound smoothness, effort against the continuous
    rating, cost of transport, and footfall and joint error against the
    reference (ADR-704, ADR-705, ADR-707, ADR-708, ADR-719).
  - `training/cadex_proxy.py` screens drives and masses on the exported model
    by replay and inverse dynamics (ADR-710, ADR-711).
- **Terrain and turning** (orun7).
  - A free base can stand on a declared course: a heightfield, or placed
    boxes, which is the form MJX trains on. A box course can be drawn from
    a seed and re-drawn per episode (ADR-714, ADR-716, ADR-717).
  - A privileged height scan reads the ground round a body (ADR-715).
    Terrain predicates judge a held-out course per evaluation seed
    (ADR-718).
  - A commanded yaw rate, scripted goal openings and command-tracking
    predicates; appendage predicates for a tail's ground contact, pitch and
    yaw (ADR-721, ADR-722).
  - `assembly.joint_dynamics` sets how stiff a joint's stop is (ADR-724).
- **The trainer learns with Brax's PPO** (ADR-712), after a benchmark on
  Unitree Go1 showed the old learner standing still where Playground's
  recipe trotted. It compiles the model once, so host memory no longer
  scales with `--envs` (ADR-695), and it can floor each step's reward
  (ADR-700).
- **The training loop** runs as agent tools with a detached supervisor
  (ADR-464). `cadex train` dispatches the offboard trainer, locally or with
  `--remote` (ADR-191, ADR-200), and takes the machine's training slot
  (ADR-543). The engine replays a policy under the command filter it was
  trained with (ADR-558).

- `mcp`, `guidance` and `style`;
- `app`;
- `budgets` (ADR-517);
- `revision`, including `backfill` (ADR-548);
- `train`, `walk` (ADR-199, ADR-282), `smoke` (ADR-352) and `evaluate`

`cadex --version` prints the product version, which comes from `VERSION`
(ADR-673).

## Tests

The suites hold contracts, not coverage (ADR-725). They pin the process
boundaries, the cadexd protocol and its response schemas, the agent's tool
surface, the HTTP API, the licence rule and the read-only dashboard. The
engine suite is 160 tests in about 35 s and the CLI suite 50 tests in about
10 s; before ADR-725 the two took about 20 minutes. Behaviour is verified by
running it.

## Project memory

The project's memory is one **governor** graph in `.flywheel/`, which is
gitignored and local to the maintainer. `STATE.md` and `PLAN.md` are
generated from it (ADR-671, ADR-672), and Hypergraph is removed. The
unattended loop that drove many of these changes is not part of Cadex
(ADR-536).

## Breaking changes and removals

- **No desktop application.** `Cadex.app`, the landing page, the demo card,
  the Blueprint Editor window, the Live editor and the in-app chat are gone
  (ADR-495, ADR-498). Nothing reads a v0.1.0 Blender document.
- **No built-in agent.** `cadex -p` and every built-in agent turn are
  removed: `walk --prompt`, `--resume`, `--model` and `--claude`, the turn
  store, `cadex comment`, the `leave_note` tool, and the scraping of
  `DECISION:` and `NOTE` lines. Use your own agent through `cadex mcp`
  (ADR-538). The Codex and pi harness backends were retired first (ADR-497).
- **The dashboard accepts no writes.** The write token and the POST routes
  for sliders, chat, comments, revision verdicts, exports and sections are
  removed (ADR-537, reversing ADR-503…507 and ADR-509).
- **The cadexd protocol drops three ops:** `live_open`, `live_step` and
  `live_close` (ADR-528). The tag stays `cadex-cadexd-v1`, because their only
  client was the shell.
- **Engine budgets** moved from a FreeCAD preference group to the project
  (`cadex budgets`; ADR-517, ADR-530).
- **xscript changes:**
  - `lib.panel` is deleted in favour of `part.envelope` and `part.panel`
    (ADR-635).
  - `fit.shells` is renamed `fit.panels` (ADR-636).
  - The single soft-body primitive and the mandated face are removed
    (ADR-480, ADR-481).
- **Policies trained before ADR-469** open with a stale-policy refusal until
  they are retrained or set aside (ADR-520).
- **The payload name changed.** It is now named from `VERSION`
  (`cadex-engine-0.2.0-<os>-<arch>`); it used to always be `0.0.0`
  (ADR-673). `package/app/bump_version.sh` is now `package/bump_version.sh`.
- **Repository leftovers removed** (ADR-675): `demo/` (the landing page's
  biped and a Blender document), `contrib/` (FreeCAD debug launchers),
  `requirements-freecad-venv.txt`, the FreeCAD GUI test harness in `tools/`,
  and the FreeCAD images, scripts and backport template under `.github/`.
  Four superseded audit docs moved to `docs/history/`.

## Known limitations

- **CI is green on both platforms for the first time since 2026-09-13**:
  run 38947903206 on `8f3d14c9` built the engine, ran both suites, staged
  the payload and passed both packaged gates on Linux x64 (19 min) and
  macOS arm64 (29 min). It failed in the pre-ADR-725 suite from 2026-09-13
  to 2026-10-15. The first run after ADR-730 caught one page-load race in a
  dashboard test, fixed in `8f3d14c9`.
- **The CLI is not packaged.** It runs from the repository against a built
  engine or a staged payload (`--engine` or `CADEX_ENGINE_ROOT`). There is
  no wheel and no published payload (ADR-030).
- **Platforms.** Built and tested on Linux x86-64. macOS arm64 passes CI,
  including the packaged gate, but has not been used by hand. Windows is
  not supported.
- **`pixi.toml` cannot be fully re-solved** (qt6/occt drift). MuJoCo is a
  pinned PyPI wheel. The GUI-era conda dependencies are still declared; the
  next release prunes them.
- **MJX is unstable on heightfields** under driven motion, so training on
  terrain uses box courses (ADR-716).
- **Turning and rough ground are unfinished.** orun7's turning policy tracks
  speed and yaw rate but runs its drives at 1.24–1.38× their continuous
  rating, and a 180° reversal was never commanded. No policy crosses rough
  ground yet, and the dashboard does not draw a course.
- **MJX training** runs from a `training/requirements.txt` virtualenv, not
  pixi. The engine checks policies but never produces them (ADR-084,
  ADR-102).
- **The North Star is not met yet.** One prompt to a walking robot,
  unattended, is still open (`STATE.md`). Creature designs blind-rate
  2.3/5, and none yet joints a head, tail or arm.
- **Non-legged tasks.** Path and coverage readings exist but are not wired
  into `assembly.success` (ADR-645).
- **`version.json` still says `name: "FreeCAD"`.** Renaming it moves the
  CMake project name.
