## Current

The shell is a Blender fork under `shell/` carrying the `mesh_agent` add-on. It is the application a user launches, and it ships the engine inside its own bundle, discovered through a `cadex-engine.json` manifest so a built application needs no configuration [rec: simple-hollow-8675] [rec: merry-eagle-4093].

- It is a **protocol client and nothing else**. It may not import anything from `src/`; `cadexd_client.py` is deliberately a plain GPL NDJSON client with no cadex imports. Being in one repository does not relax this [rec: simple-hollow-8675] [rec: merry-eagle-4093].
- Product surface: viewport, chat, parameter sliders, model tree and script view; Cadex File and Edit menus; a saved-layout startup file rather than a Python template [rec: open-dew-7293]. Plus the Wiring editor [rec: crisp-glacier-6395], the Environment/Policy/Training/Live editors and the force-arrow overlay [rec: mellow-hawk-8610], `render_views` and the section-cage overlay [rec: solemn-chart-6274], **File > Link Part... / File > Refresh Linked Parts** with the `link_part` backend trio behind them [rec: ancient-current-9419], the Dimensions overlay with its Measure button [rec: forest-wind-3489], and the **Section View** — a third view toggle in the same button row, aimed by an axis/offset/flip box in the parameters editor [rec: grand-peak-3688].
- The model reaches the shell through **19 MCP tools** in `tools.py` [rec: ancient-current-9419] [rec: grand-peak-3688] [rec: zesty-cove-4881] — the newest is `section_view`, which cuts the model open so the agent can see inside its own work, classified exactly as `collision_view` is: in neither `MUTATING_TOOLS` (looking must not enter the undo stack) nor `_ENGINE_TOOLS` (it never speaks to cadexd) [rec: grand-peak-3688]. **`get_script` takes optional `offset`/`limit` line arguments** (ADR-140): no arguments serves the whole script exactly as ADR-044 requires, and either argument serves a window behind a banner carrying the range, the totals and the next offset to call. It closes a gap where the *host's* tool-result cap — not ours — had no compliant response, and an agent improvised by deleting comment blocks out of a user's script to make a **read** smaller [rec: shy-glade-0050].
- **`cadex_dimension.py` draws a declared measurement as a drawing sheet would** — extension line at each anchor, dimension line between them, the number in the middle with the line broken around it. Everything except the two anchors is computed **in screen space**: the offset direction is perpendicular *on the screen*, so it cannot go edge-on however far you orbit — by construction rather than by care — and gaps, ticks and text are pixel constants, so a 2 mm boss and a 2 m beam read identically at any zoom. Below `MINIMUM_SPAN_PX`, which is what looking straight down the measured axis gives you, it degrades to a leader still carrying the number, so the value survives every viewing angle. One `POST_PIXEL` pass where the force arrows need two, because a dimension is not a world object [rec: forest-wind-3489].
- It creates **no Blender objects**, so unlike `cadex_collision` and `cadex_cage` it needs no sibling collection and cannot be swept by the contract GC. The Measure button queues a request on the pin queue rather than writing the script, so **the script keeps exactly one author** [rec: forest-wind-3489].
- **`cadex_section.py` cuts the model open, and the cut face is filled** (ADR-148). A hidden, scaled unit-cube cutter plus a Boolean DIFFERENCE modifier on each hydrated solid, and an eight-node geometry-nodes clip on each edge wire — two mechanisms because the model is drawn as two kinds of object and a boolean has nothing to say about a mesh with no faces. Measured **6.3 ms** per offset change, against the 650 ms slider bar it shares a viewport with. It is a **view, not a feature**: nothing reaches the engine, nothing is written to the script, and the gate asserts the accepted revision is unchanged either side of switching it on. Because it is modifiers rather than an overlay it survives a rebuild for free — hydration swaps the mesh datablock and keeps the object — so `cadex_hydrate` needed no change at all and `cadex_backend.hydrate` gained one `refresh` call, for new outputs only. `render_views` suspends it, because a cut model is not what was built [rec: grand-peak-3688]. It changed **nothing in `modes.py`**: the Cadex system-prompt overlay is capped at 3500 characters and sits at 3447, so the workflow sentence written for it did not fit and the cap was not raised [rec: neat-tower-5715].
- **`cadex_explode.py` spreads the assembly apart, and the engine authored every number** (ADR-149). A toggle plus a factor slider 0→1 interpolating the engine's exploded-view display record: staged windows (stage *i* of *N* owns factor [i/N, (i+1)/N]), lerp positions, hemisphere-corrected slerp orientations, leader lines as one wire object in a sibling `Exploded` collection growing with each component's own staged progress. Poses ride `matrix_world` — the channel hydrate already owns — and are re-applied by the hydrate hooks, so engine poses land first and the spread lands on top, always; delta channels were rejected as a second owner for one question. It **refuses while a simulation is baked**: F-Curves and `matrix_world` writes cannot share an object honestly, so mutual exclusion rather than layering. One exploded view per model; two is refused naming both. The `exploded_view` tool is classified exactly as `section_view` is, `render_views` suspends the spread, and the gate's first exploded assertion compares the factor-0.5 viewport pose against the pure half's own prediction — the re-application risk made a test [rec: zesty-cove-4881].
- **The diff rule that governs every change here**: every line of our `shell/` diff is under `shell/scripts/addons_core/mesh_agent/` or `shell/tests/python/`, and the inherited Blender tree is untouched. `docs/BLENDER-TREE.md` §2a is eight files and must stay eight [rec: open-key-6334]. Linked parts held to it — +541/-5 across six files [rec: ancient-current-9419] — and so did dimensions: one new file (650 lines) plus +331/-3 across six, nothing in §2 moved [rec: forest-wind-3489]. The section view held to it too — one new file plus edits to six add-on files and the gate suite [rec: grand-peak-3688] — and so did the exploded view: one new file plus edits to the same six, nothing inherited touched on the shell side [rec: zesty-cove-4881].
- Nothing in `shell/` imports mujoco, and a test asserts it. The shell never learns MuJoCo exists — a policy rollout reaches it as the simulation trace it already knew how to play [rec: sage-wood-0687] [rec: open-key-6334].
- The product gate is `pixi run gate`: one `CADEX-BLENDER-GATE` line against the built bundle, with picking ≥ 0.99 and slider median ≤ 0.65 s. **696 checks, `"ok": true`** as of 2026-08-10 [rec: simple-hollow-8675] [rec: merry-eagle-4093] [rec: forest-wind-3489] [rec: shy-glade-0050]; still `"ok": true` on 2026-08-17 with the section-view test in it, picking 372/372 and slider median 0.494 s [rec: grand-peak-3688]; still `"ok": true` on 2026-08-18 with the exploded-view test in it, slider median 0.496 s — after one run at 0.762 s under post-build machine load, a flake the re-run disproved [rec: zesty-cove-4881].

**A shipped defect, found and fixed while adding linked parts.** `cadex_backend._assets_in` filtered Save-As's carry-forward on the three-suffix `ASSET_SUFFIXES` the shell mirrors by name, so a Save-As would have **dropped every `.cxpart`** and left the new file with a script that could not run — ADR-046's bug arriving on a new file type. A separate `CARRIED_ASSET_SUFFIXES` fixes it and the gate pins it. **The identical gap is still open for `.cxpolicy`**: it was named and deliberately not fixed, because carrying trained weights on every Save-As is its own decision [rec: ancient-current-9419].

## Negative knowledge

- [scope: shell/ edits outside mesh_agent | confidence: high | evidence: open-key-6334] Every line added to the inherited Blender tree is a future merge conflict. Adding one is a decision to bring back, not a fix to slip in — the empty-diff rule was retired but the boundary it stood proxy for was not, and BLENDER-TREE.md section 2a must stay eight files.
- [scope: gate coverage | confidence: high | evidence: solemn-chart-6274, grand-peak-3688] The gate runs blender --background, so anything needing a real VIEW_3D is not covered by it. Verify those by driving the built application and say so, rather than implying coverage the gate does not have. Read forward as well as backward: where two mechanisms would both do the job, the one the gate can *see* is worth real cost. The section view is a boolean partly because `rv3d.clip_planes` needs a `RegionView3D`, which `--background` does not have at all, and would also have been absent from every offscreen render the agent takes.
- [scope: reading the gate's result | confidence: high | evidence: forest-wind-3489] **`pixi run gate` exits 0 when a test raises mid-run.** An `AttributeError` in one test ended the suite after 355 checks with no `CADEX-BLENDER-GATE` line at all, and the exit code was still 0. Checking the exit code is not enough — the `"ok": true` line has to be read. Pre-existing and not fixed.
- [scope: any new asset suffix | confidence: high | evidence: ancient-current-9419] Widening the engine's `_STORED_ASSET_SUFFIXES` is free, but the shell carries its **own** suffix list for Save-As and it does not follow. A new asset type that is not added there is silently dropped by Save-As, and the failure surfaces later as a script that cannot run in the copy.
- [scope: asserting anything about an output from the viewport | confidence: high | evidence: ancient-current-9419, forest-wind-3489] The viewport polygon count tells you nothing about what an output *is* — the mesh in the viewport is a tessellation whatever it came from, so a 40-face linked BREP solid shows 520 polygons and a measurement shows whatever its subject shows. A gate assertion on `obj.data.polygons` looks like it proves this and does not; **this assertion has now been written and thrown away twice in this tree.** For a drawn overlay the check that works is calling the drawing function with a made-up region and view matrix — which is why `drawing_for` is a function rather than something living inside a draw handler.
- [scope: an overlay that must read from any angle | confidence: high | evidence: forest-wind-3489] A plane fixed in the model is the wrong home for a dimension: any such plane goes edge-on if you orbit far enough. Compute in screen space instead, and the failure mode is removed by construction rather than defended against. Likewise a circle's in-plane basis must not come off a fixed reference axis — a bore drilled down Z is the single most common thing anyone measures, so the naive choice fails on the first real model rather than an exotic one; take the basis off the world axis least parallel to the circle's own.
- [scope: any per-tool exemption from a result cap | confidence: high | evidence: shy-glade-0050] `MAX_RESULT_CHARS = 4096` governs every mesh tool **except** `get_script`, and that unannounced exemption is what an agent got wrong — it concluded "the engine only shows me a 4 KB window", which was false, and never checked. The general lesson is worse than the specific one: **a tool that cannot serve part of a thing invites the model to make the thing smaller**, and the model has write access. 122 lines and 4.8 KB of a user's design rationale were deleted to advance a read.
- [scope: adding a table to docs/INTEGRATION.md | confidence: high | evidence: forest-wind-3489] Its two contract tables are scraped by regex on any line starting with `` | ` `` — across the whole document for ops, and within the response section for keys. A new markdown table anywhere in the file is read as protocol rows. Document nested records as a bullet list.
- [scope: adding a line to the Cadex system-prompt overlay | confidence: high | evidence: neat-tower-5715] `modes.CADEX_OVERLAY` is capped at **3500 characters** by `bl_mesh_agent.py` and sits at **3447**. The next workflow sentence is not a sentence, it is a decision about which existing one to remove — and the bar that text is held to is the collision line's: it earned its place with two shipped bugs. Note also that this guard lives in `bl_mesh_agent.py`, which `pixi run gate` does **not** run — `pixi run gate` was green with the over-budget overlay in place.
- [scope: measuring the model from the shell | confidence: high | evidence: grand-peak-3688] **`obj.bound_box` reflects EVALUATED geometry, not the object's data.** A 20 mm cube with a boolean that cuts it at z = 5 reports a top of 5 — measured, not assumed. Anything that both modifies the display objects and derives numbers from their extent feeds back on itself: the centre of an axis drifts into the surviving half, and a range a person is dragging against moves as they drag. Read the mesh datablocks (numpy `foreach_get`) when the number must mean *the model as built*, and suspend any such modifier before measuring for a camera fit.
- [scope: where model state may live | confidence: high | evidence: forest-wind-3489] Scene data in the `.blend` is much cheaper than a script declaration and is the wrong answer for anything that is part of the model: it would be the only model state not in the script — lost by a Save-As, unauthorable by the agent, and unable to travel in a `.cxpart`. In the script it is anchored by selector and recomputed, which is what makes it follow a parameter.
