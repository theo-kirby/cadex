## Negative knowledge

- [scope: happy-dawn-1960's initial F1 completion claim | confidence: high | evidence: steady-quartz-9854] The original forty-pair slice omitted failing pairs and did not meet F1. The complete-list correction and its full CLI verification supersede that claim.
- [scope: the fit reply as a detector of undeclared attachments | confidence: high | evidence: stormy-snow-5452, honest-sky-8719] A gap that clears the default threshold with no declared intent is never a failing row, so the agent does not act on it. Seeing the measurements is not the same as knowing which pairs should touch. Since ADR-370 the specific case that bit Heron is *reported* — a pair welded by a `fixed` joint and measured apart shows as `not touching` in `fit.attachments` — but it is deliberately still not a failure, so nothing in the failing set or the verdict makes the agent act on it.
- [scope: `contacts=` as the declaration for an intended gap narrower than the 0.1 mm undeclared-pair default | confidence: high | evidence: fierce-falcon-2378] It is not one. A `contact` intent fails at `distance > 1e-3`, so declaring `contacts=` on a 0.05 mm bearing seat moves the row from `below clearance` to `missed contact` — a renamed failure that reads like progress. The declaration is `clearances=[(a, b, 0.05)]`, and ADR-372's sentence offering `contacts=` for those seats is corrected in place by ADR-373.
- [scope: holding every undeclared pair to one default gap | confidence: high | evidence: sharp-glacier-3405] A default written for pairs nobody declared punishes designs that did declare, in the joint graph rather than in `contacts=`: half of Finch's below-clearance rows were welds meeting at 0.0 mm, which is what a `fixed` joint asks for. Read what the assembly already says about a pair before applying a threshold to it.
