**Pair clearance now measures a component where the assembly puts it (ADR-241, commits `cf3b77a6` and `0a1a1fbe`).** The cause was read in the kernel: an `App::Link` *replaces* the linked object's placement with its own instead of composing them, and every `lib.*` part carries its transform on the shape because `lib._place` uses one `part.transform`. `_measure_clearance` read `component.Shape` and so measured catalog bodies in their canonical origin frame. The fix is one helper, `_component_world_shape`, taking the linked shape with `component.Placement * shape.Placement` — the composition the MJCF export already uses, so review now agrees with the physics; a container source keeps `component.Shape` and an unreadable source falls through to the old error path. A real-kernel `FreeCADCmd` regression over four `App::Link` components **fails on the pre-fix source** (shape-placed pair 0.0 mm / ≈1000 mm³) and passes after it (40.0 mm / 0 mm³; the both-frames body at 150–160 mm; a real 2 mm overlap at its true 200 mm³). Engine gate 2076 passed / 52 skipped; CLI gate 195 passed, zero skips. On the pan-tilt assembly, rebuilt through `cadex params` and re-reported with `cadex clearance` against the dev tree: servo_pan/servo_tilt clear at 25.9 mm, base/servo_tilt clear at 57.9 mm, base/servo_pan intersecting at 111.264 mm³ — and three real contacts the wrong frame had hidden now appear (pan servo in the yoke 18.857 mm³, tilt servo in the yoke arm 75.430 mm³ and in the head plate 73.500 mm³), so the error had suppressed true findings as well as inventing false ones [rec: light-timber-5868].

## Negative knowledge

- [scope: named-angle probe using the existing background Blender renderer after accepted hinged-arm hydration | confidence: high | evidence: zesty-aspen-6846] All four valid blueprint views and `render_views` explicitly refuse background mode. The override probe's exit 0 records returned errors, not a rendered PNG. CPU projection must snapshot revision-dependent display buffers before another rebuild invalidates their paths.

- [scope: inventory inspection replies exceeding the 1 KiB per-key budget | confidence: high | evidence: lawful-ivy-4474] Paging only `/components` is insufficient: catalog totals, uncatalogued sources, component rows and nested strings can also be previews. The former reader failed converting `/catalog_counts` to an integer and could lose oversized names; recursive expansion is required and regression-tested.

- [scope: `_measure_clearance` on an `App::Link` whose linked object carries its own placement — every `lib.*`-placed catalog part | confidence: high | evidence: empty-banner-7438, light-timber-5868] `App::Link` replaces the source's placement rather than composing it, and `Part.getShape(link)` does the same; only a link to an `App::Part` container composes. `SimpleNamespace`-stubbed tests cannot see this, which is why three earlier walks on hand-modelled parts never did. Fixed for the pair check by composing `component.Placement * shape.Placement`, pinned by a real-kernel regression that fails on the old source.
- [scope: `_clearance_at_frame`, the swept clearance inside the simulation trace, for `lib.*`-placed bodies | confidence: high | evidence: light-timber-5868] Reads the same link shape and has the same frame defect; left unfixed by decision (ADR-241) because it runs per pair per frame over thousands of frames and composing a shape copy there needs its own cost measurement first. Until it lands, a swept breach distance for a catalog-placed body is not to be believed.
- [scope: the installed bundle after commit `cf3b77a6` | confidence: high | evidence: light-timber-5868] Not rebuilt or restaged; a walk run with `--engine <bundle>` still reports the pre-fix clearance numbers. The corrected pan-tilt report came from the dev tree (`"source": "dev-tree"`).
