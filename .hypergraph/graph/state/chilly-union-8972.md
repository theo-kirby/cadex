## Current

`cli/` plus the `./cadex` shim is a second **front end** and the third client of the cadexd protocol: no Blender, no display, no shell code. Ordinary projects need a built engine alone [rec: jolly-walrus-3692]; native Blender recipe projects additionally require `CADEX_BLENDER_EXECUTABLE` [rec: simple-bramble-8616].

- **Twelve** subcommands — `-p`, `params`, `script`, `export`, `link`, `asset`, `train`, `walk`, `inventory`, `clearance`, `render`, `section` — of which only `-p`, and `walk` when given `--prompt`, spend tokens [rec: placid-lily-5624] [rec: silver-key-8483] [rec: fair-rose-5950] [rec: falling-birch-1503]. The point is a cost asymmetry: one expensive turn authors a *parametric* script, and a cheap loop then sweeps its parameters, pulls a part in from another project, stores a policy, or dispatches a training run, with no model in the loop at all [rec: jolly-walrus-3692] [rec: ancient-current-9419] [rec: restless-harbor-4224] [rec: amber-moon-0981] [rec: shy-cabin-0798].
- Its whole model-facing tool surface is **generated from `OP_ARG_SPECS`**, so it cannot drift from the contract it drives [rec: jolly-walrus-3692]. `link_part` arrived that way — the model gained it with no CLI code at all, and `cadex link` exists only for the token-free path [rec: ancient-current-9419]. `put_asset` joined `CLI_TOOL_OPS` last (`source_path` required, `name` optional), with prose saying the reply's sha256 is the digest `assembly.policy` requires [rec: restless-harbor-4224].
- It cost **no engine change and no protocol change**, which is the evidence it was built to produce: a third client that had needed the contract widened would have been evidence against the contract [rec: jolly-walrus-3692] [rec: simple-hollow-8675]. ADR-190 through ADR-194 held to that: no protocol op, no engine change, no `shell/` diff [rec: restless-harbor-4224] [rec: amber-moon-0981] [rec: keen-sail-4481] [rec: odd-fern-7024] [rec: sunny-fern-8059].
- `cli/` is **LGPL and `shell/` is GPL**, and the boundary is one-way and hard. Copying a line of the shell's client into `cli/` relicenses the engine side; derive from the engine-side precedents instead [rec: jolly-walrus-3692] [rec: lone-haven-0640].
- **It reads the store's deliverables without being able to make one** (ADR-150): `inspect scope=blueprint` is served — the asymmetry with the absent `image` scope is deliberate, a reference image being a shell-only input while a blueprint sheet is a stored deliverable of the project — and `export --blueprints` copies stored sheets into `--out` under their store names, entirely through inspect. `put_blueprint` is deliberately absent from `CLI_TOOL_OPS`, for the stored blueprint-sheet path; the later CPU `render` command writes project review previews instead [rec: silver-key-8483] [rec: windy-wolf-5012].
- **`export` hands over every staged output, not only the BREP ones** (ADR-189, `docs/CLI.md` §3) [rec: wise-tooth-2750]. It converts BREP outputs to STEP/STL and copies every other staged artifact — a mesh's `.ply`, the MJCF `.xml`, the task, policy receipt and rollout trace `.json` — into `--out` under its **staged** filename, naming each in the `--json` envelope's `files` under its suffix; only an output with nothing staged is skipped. The staged basename is kept because the task bundle names its model by it, so the `--out` directory is a training bundle `training/cadex_train.py` accepts unchanged. Before this the audit found every non-BREP output `skipped` [rec: sweet-light-3396].
- **`asset` is the headless door into the project store** (ADR-190, `docs/CLI.md` §2–§4) [rec: restless-harbor-4224]: `--put FILE` is repeatable (a policy travels with its receipt), `--name` renames when there is one file, and the store's listing — name, bytes, sha256 — comes back as the optional `assets` envelope field, which is what a pipeline pipes into `cadex script --set`. With no `--put` it lists the store by following `inspect scope=assets`'s page chain. Usage errors fire before the engine runs; the engine's refusal is exit 3. No `--rebuild` flag by decision.
- **`train` dispatches the offboard trainer** (ADR-191, ADR-192, `docs/CLI.md` §2–§4, §8) [rec: amber-moon-0981] [rec: keen-sail-4481]: `--iterations`, `--envs`, `--seed`, `--label`, `--init-from`, `--task`, `--name`, `--put`, `--timeout`, `--trainer-python`, and since ADR-192 the ADR-161 curriculum pair `--init-from-parent-task BUNDLE` and `--init-from-task-change REASON`, passed through by name and refused apart from `--init-from` as a usage error before the engine runs. It rebuilds, exports the bundle, runs `training/cadex_train.py` and, with `--put`, stores the policy; the optional `training` envelope field carries the trainer's receipt as printed. The interpreter is `--trainer-python`, then `$CADEX_TRAIN_PYTHON`, then `<repo>/.venv`, then `~/cadex-train-venv`, and is never created. `cli/` depends on `training/cadex_train.py` by path and on its flag names by test (read from the trainer's parser), and `training/` stays out of every payload. Measured 18.5 s wall for 2 it × 8 envs on the §7b toy; a warm retrain across a task change 17.8 s. `docs/CLI.md` §2 carries an **Iterating** paragraph: the `policy_on` switch convention and the four commands (`params --set policy_on=0 --set <change>`, `train` with the pair, `script --set` for the digest, `params --set policy_on=1`).
- **The CLI scaffolds and maintains the project's documents** (ADR-193, `docs/CLI.md` §2 has the table of the four files and who writes each) [rec: odd-fern-7024]: `cadex_cli/project_docs.py` writes `ARCHITECTURE.md`, `DECISIONS.md` and `PROGRESS.md` on the first visit from `_engine_session` (idempotent, never overwriting); `system_prompt(api, project_docs=...)` pastes them into every `-p` turn, bounded at 8 000 characters each, under a **THE PROJECT IS A CODEBASE** paragraph in the overlay; `main()` appends one `PROGRESS.md` row after every accepted run with the numbers the run produced (never for the script print or the store listing); a turn's closing `DECISION:` lines are recorded as numbered ADR entries after the turn. The agent has no file tool by decision.
- **It records comparisons and attempts project-owned commits** (ADR-194). Progress rows retain the previous value, digest and delta [rec: sunny-fern-8059]. Three real staged `script --set` acceptances qualify ownership: a fresh root initializes Git, installs default ignore rules when absent and commits; an existing project-root repository retains its ignore configuration and commits all working changes, including unrelated edits and the working versions of staged files; a nested project without its own `.git` gets documents and a progress row but no initialization or automatic commit, preserving the parent HEAD, index and cached diff. All pre-existing user-file bytes were preserved; the existing root's staged/unstaged distinction was consumed by commit-all, not preserved. Fresh defaults exclude checkpoints and traces while including stored policy assets [rec: fresh-flint-1505]. CLI/module guidance and DECISIONS/PROGRESS scaffolds now distinguish these cases: a progress row alone proves no commit, and `committed <sha>.` in command notes reports success. Missing Git or a failed commit does not invalidate acceptance; existing project documents are not migrated. Full CLI gate: **206 passed, no skips** in 224.33 s. Fresh roots with pre-existing ignore files, linked worktrees, missing Git and commit failure were not runtime-qualified by this experiment. Reconcile judgement: the finite documentation mismatch is closed, with Git behavior unchanged and status retained as `working` [rec: little-fern-0464].
- **`walk` is the one-command lifecycle** (ADR-199, `docs/CLI.md` walk section) [rec: shy-cabin-0798]: `cadex walk --out DIR [--iterations N --envs N --timeout S] [--set k=v --name NAME.cxpolicy] [--prompt ...]` runs the legs in order — rebuild, train, store, the digest edit as a two-literal rewrite of the one `assembly.policy` call, the verified rollout — writes `review.json` under `--out` and commits it as the walk's own commit. `cli/tests/test_walk.py` pins the digest edit and review reader at string level, leg order, flags and refusals against a fake `cadex`, and the two real toy walks. Qualified on the repo-owned toy; the scaffolded `.gitignore` gained checkpoint and trace hygiene with it.
- **`train` and `walk` gain `--remote` and `--allow-cpu`** (ADR-200, `docs/CLI.md` §2, `training/SETUP.md` §d) [rec: green-delta-7130]: the train leg's command becomes `training/remote_train.sh train <bundle> <out> [--allow-cpu] -- <the same trainer flags>`, the flags split out of `trainer_command` into one `trainer_flags` source, and a shared usage check refuses `--remote` with a warm start before the engine runs. `training.trainer_out` carries the box's path, the returned policy is checked against the receipt's sha256, a dispatcher `FAIL:` reaches the envelope's `error`, and a non-zero exit shows the stdout tail. The CLI reads none of `.remote.env`. Offline-tested only, against a stand-in dispatcher. A `train --remote` row in `PROGRESS.md` ends in `(remote)`, and the `ARCHITECTURE.md` scaffold carries a `## Training` section pinned to `docs/CLI.md` by a test [rec: wild-marsh-9611].
- **`train --dry-run` plans the leg instead of running it** (ADR-255, commit `007b4735`, `docs/CLI.md` §2, `training/SETUP.md` §d) [rec: candid-otter-2615]: the flag is on `train` alone, and its branch sits after the trainer command is built and before the trainer is spawned, so it plans exactly the command that would have run and returns `EXIT_OK` without the trainer and without the `put_asset`. The optional `training_plan` envelope field names the four files the leg would touch (`bundle`, `model`, `policy`, `stored_asset`) and the ordered `steps`, with `executed: false`; the two transport step names are the module constant `REMOTE_TRANSPORT_STEPS`, so the test asserts against the source rather than a literal. `resolve_bundle_model` reimplements `remote_train.sh`'s inline model resolution — the recorded relative path against the bundle's grandparent, then the basename beside it — so an unresolvable model is a refusal here rather than a failure on the box mid-copy. No ssh, no `.remote.env` read, no engine, protocol or `shell/` change; 348 insertions over `cli/**`, `docs/**` and `training/SETUP.md`. CLI gate **225 passed, 0 skipped**.
- **`inventory` is the first headless review call** (ADR-236, commit 5045847a; `docs/CLI.md` file map now also lists `train.py`, `walk.py` and `project_docs.py`) [rec: fair-rose-5950]: `cadex inventory` — no AI, no tokens, no rebuild — reads `inspect scope="inventory"` over the pinned accepted attempt, following the `/components` page chain rather than trusting the summary reply (whose `components` key becomes a preview stub past the 1 KiB per-key budget), and renders `docs/inventory.md` in the project: one row per placed component with its `source_output`, catalog id where there is one, placement and source facts, a catalog roll-up and a "Not from the catalog" list; the envelope note reads `inventory: N component(s), M catalogued`. The first generated doc under a project's `docs/`, marked as such in its own first line. No protocol change (`inspect` already takes a scope and answers a generic value), so `OP_ARG_SPECS`, the goldens and `shell/` are untouched; `docs/INTEGRATION.md`'s `inspect` row documents the scope. Real-engine test: a plate with two catalogued M3 bolts; CLI suite **145 passed** on the built engine.
- **The strict reply validator no longer hard-fails on an inspect exception** (ADR-195) [rec: fierce-moss-6382]: the CLI validates every reply strictly, and the engine's hand-built `INSPECTION_FAILED` frame (from `inspect scope=document` throwing) violated `FAILURE_RESPONSE_SPEC`, so mid-turn it became a `CadexdError` where the shell, which never validates, carried on [rec: sweet-light-3396]. The engine now builds that frame through `tool_failure` and it passes `validate_response`, so the agent reads it as a refusal like every other tool failure. No CLI change; the suite stayed at **117 passed** against the built engine.
- **GUI-attached ownership is sequential** (ADR-201, `docs/CLI.md` §§2 and 5): the CLI's advisory lock is per command and released before the progress row and commit; the shell takes no lock. Its stale-revision retry keeps the original mutation and can silently overwrite CLI-accepted source or values. Rebuild Model or reopen is required before GUI editing resumes. The scaffold/doc wording is pinned by a test; no runtime fix or GUI exercise is claimed [rec: red-comet-9710] [rec: grand-fjord-0624].
- Verified end to end on Linux, in CI, against both a build tree and a staged payload; since 2026-08-19 also exercised by hand on macOS [rec: windy-wolf-5012]. - **Payload resolution checks schema agreement, not payload completeness** (`docs/CLI.md` §6, ADR-061 correction dated 2026-09-08, commit c84fd306) [rec: tiny-haven-0347] [rec: keen-pebble-3574]. `resolve_engine` checks the manifest's named paths, loads the module dir's `CadexdProtocol`, and refuses only when the manifest's `protocol` and the module's `PROTOCOL_SCHEMA` are both nonempty and unequal. A disposable resolver-only probe pinned the boundary: a mismatched schema is refused with the `declares protocol` error, while a matching schema resolves with `CadexWorker.py` and `CadexAssemblyAPI.py` absent; the existing resolution suite passed 10 with no skips [rec: tiny-haven-0347]. The guidance and the resolver comment used to promise that a payload assembled out of two trees fails before a frame is sent; they now state the check and its limit — agreement proves neither worker completeness nor shared source provenance. Runtime is unchanged (resolver AST identical before and after); no validator, fingerprint or new test was added by decision. Full CLI gate against the refreshed installed engine: **195 passed, zero skipped** (201 s, 1.16 GB peak process-tree RSS, no cutoff) [rec: keen-pebble-3574]. **`cadex clearance` writes `docs/clearance.md` through `inspect scope="clearance"` (ADR-237).** It reads every assembly pair, including separated pairs, follows all pages/previews, and reports names, labels and catalog ids with exact minimum distance and common solid volume at the initial solved pose. Finite nonnegative thresholds are applied without rebuilding or changing the content digest. Verdicts distinguish intersection, below-clearance, clear and unknown; legacy/failed/unsolved measurements never become clear, and no assembly is unavailable. Exit 0 means the report was written, not that all pairs are clear. Defaults are 0.1 mm clearance and 1e-6 mm³ intersection volume. This is neither swept-motion checking nor large-assembly cost qualification [rec: falling-birch-1503].

**`cadex render --project PROJECT --json` is the CPU-only named-angle review call (ADR-239).** A standard-quality rebuild is snapshotted under the normal CLI project lock before another engine request can invalidate display buffers. Bounded geometry/instance/pixel work, solved placements and pixel-center depth produce front/top/right/iso SVGs containing lossless 512px raster images, plus `review/render/summary.json` with accepted revision, digest, bounds, camera bases, approximation and timings. The five generated review files and PROGRESS.md are committed. Missing meshes/poses and invalid buffers refuse rather than guess; a refusal can leave older successful artifacts carrying their original revision. Arm and curved-assembly views were visually inspected and tested. No graphics dependency or engine/protocol change. Subpixel detail, shell visibility and motion envelopes are not guaranteed [rec: silver-key-8483].

**Named-plane sections are delivered (ADR-240).** `cadex section --plane XY|XZ|YZ --offset-mm N` writes committed revision-bearing SVG/JSON under `review/section/` from bounded accepted world-space tessellation. Closed per-object contours use even-odd fill to preserve cavities and solved placements. Plane contacts, open/branched or duplicate/collapsed segments report unsupported; outside cuts report empty. Acquisition, revision, input and write failures remain command errors, and retained old files are not current success. A placed, rotated bored block verifies cavity areas and bounds; all three planes and refusal cases are tested. Full built-engine CLI gate: 188 passed, zero skipped; final section gate: 7 passed. This is a qualified tessellation cut, not an exact solid section or a solid-validity/motion certificate [rec: placid-lily-5624].

## Negative knowledge

- [scope: cli/ on macOS | confidence: medium | evidence: jolly-walrus-3692] Nothing in the CLI is macOS-hostile, but it has never been run there by hand and 'should work' is not evidence. Expect the macOS CI job to be the thing that finds anything.
- [scope: copying code into cli/ | confidence: high | evidence: jolly-walrus-3692] Copying a line from the GPL shell's client into LGPL cli/ relicenses the engine side. It is not a judgement call — derive from the engine-side precedents instead.
- [scope: giving the CLI agent a tool that spawns the trainer | confidence: high | evidence: amber-moon-0981] Not taken by decision: the agent has no shell, and a fifteen-minute subprocess inside a model turn is the wrong shape. The leg is the caller's or a pipeline's, one command, and the overlay says so.
- [scope: a warm start on the remote train leg | confidence: high | evidence: green-delta-7130, candid-otter-2615] Refused as a usage error before any leg: `remote_train.sh` copies the bundle and the model out, not the `--init-from` policy, so `--remote` trains cold until the dispatcher carries the pair. `--detach` is not passed through either; a walk waits for its leg. `--dry-run` does not bypass the check — the usage error fires before the plan is built.
- [scope: certifying a payload's coherence at CLI resolution | confidence: high | evidence: tiny-haven-0347, keen-pebble-3574] Equal manifest and module schema strings do not establish identical code or complete worker imports. Not taken: version fingerprints or a new validation policy; the false guarantee was removed from the guidance instead, and the packaged lifecycle gate remains the check that proves a payload.
- [scope: a `params --drop-policy` flag or an engine op for iterate | confidence: high | evidence: keen-sail-4481] Not taken: `set_params` already accepts a dropped output, so a script convention (`policy_on`) does the job with no CLI flag and no engine change; adding a `flag(...)` parameter type was also declined because parameters are numeric only and the convention does not need one.
