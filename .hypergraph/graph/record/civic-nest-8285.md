## What

Per-run retained-artifact disk use in the review panel (ADR-322). `review_record.run_disk_use(root, record, others)` counts what one run keeps under `runs/<name>/` from permitted project-local files only: every regular file that resolves inside the run directory, each inode once (a hard-linked pair is one file and one `hardlinked_entries`), no symlink followed (linked entries listed as skipped with the reason), split by top-level subdirectory, from `stat` alone with nothing read or hashed, bounded at `DISK_USE_ENTRY_LIMIT` (20 000 entries) past which it reports `truncated` and a floor. Every reference the record names is sized with the reader's own status words (`retained` with bytes, `missing` without, `refused` and never opened, `not recorded`). A `project_artifacts` reference resolving outside the run is sized under `shared_bytes` and `shared_with` names the other runs whose records cite the same path, so a policy asset a training run and its playback run both cite is counted once for the project. A run directory that escapes the project is `unreadable` and nothing under it is stat'ed. The new `ReviewProject.detail(name)` attaches it to `/api/run/<name>` beside the full telemetry; the run list never carries it. The page's Artifacts card shows the total, the per-directory split, the skipped links, the shared references with the sharing runs, a size column on the artifact table (`missing — nothing on disk`, `refused — not read`), and the video size in each video label; the accepted view says it has no run to count. The persistent Lark dashboard on port 8765 was restarted onto it with no trainer active and verified over the private address.

## Result

The persistent private URL serves `ot5-lark-copy85` on the ADR-322 server (new MainPID 166905; a fresh visit selects `lark98-final`). Its panel reads 895.8 KB in 37 files under `runs/lark98-final/`, equal to an independent walk (917 305 bytes, 37 files); `by_dir` is rollout 792 728, run root 40 842, train 37 636, render 23 992, project-docs 22 107; the policy asset `assets/lark98.cxpolicy` (84 571 bytes) is shown outside the run's total, shared with `lark98`; thirteen runs hold 9 576 634 bytes under `runs/` (probe-computed, not served). `lark98-checkpoint20` opened as history with its own count (860 282 bytes, 38 files) and its video kept playing through two polls; the route back to current works. The run list carries no disk block, so the ADR-321 poll bound holds. Apparent sizes (`st_size`), not blocks: `du` reports more.

Concerns and assumptions: the count is one `scandir` walk plus a `resolve()` per entry of the selected run on each two-second poll of the detail — bounded per run and cheap at Lark's ~40 files, and capped at 20 000 entries; a run with tens of thousands of files would show `truncated` rather than hang. `shared_with` compares recorded project-relative path strings across records that resolved cleanly, not inodes, so two records citing the same file by different paths would not be linked. The artifacts table is still rebuilt on every render, as before; the added size column raises the constant idle-poll node count by two nodes per artifact row. No new dependency. The unreconciled tail is now three records (`quiet-pebble-5566`, `dusty-fjord-4501`, this one): the next iteration is the scheduled reconcile pass, per the charter and the critic.
